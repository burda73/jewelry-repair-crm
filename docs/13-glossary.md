# 13. Глоссарий

Термины, которые используются в коде, документации и интерфейсе. Единая терминология
важна: если в коде `Performer`, а в ТЗ «мастер», разработчик и заказчик говорят о разном.

## Бизнес-термины

| Термин | Значение | В коде |
|--------|----------|--------|
| **Заказ** | Единица учёта ремонта: от приёма изделия до выдачи клиенту | `Order` |
| **Номер заказа** | Человекочитаемый идентификатор, формат `МСК1-2509-000142` | `Order.orderNo` |
| **Изделие** | Физический предмет, принятый в ремонт; в заказе может быть несколько | `Item` |
| **Магазин** | Точка приёма и выдачи | `Store` |
| **Цех** | Производственная площадка, где работают ювелиры | `Workshop` |
| **Мастер-ювелир** | Исполнитель ремонта. **Не пользователь системы** | `Performer` (не `User`) |
| **Менеджер производства** | Сотрудник, ведущий взаимодействие с производством и ювелирами | роль `PRODUCTION_MANAGER` |
| **Партия** | Набор заказов, физически перемещаемых одной поставкой | `Batch` |
| **Акт приёма-передачи** | Документ о передаче партии между магазином и цехом | `BatchAct` |
| **Прейскурант** | Версионируемый справочник типовых работ с ценами | `PriceListVersion` |
| **Позиция прейскуранта** | Конкретная работа с ценой | `PriceListItem` |
| **Калькуляция** | Расчёт стоимости конкретного заказа | `OrderWork` + `OrderStone` |
| **Работа** | Строка калькуляции: вид ремонта по прейскуранту или нетиповой | `OrderWork` |
| **Камень** | Отдельная строка калькуляции: стоимость камней (ТЗ п. 2.3) | `OrderStone` |
| **Корректировка** | Изменение суммы после приёма, обязательно с причиной | `CalcAdjustment` |
| **Согласование** | Фиксация договорённости с клиентом по сумме и сроку | `Approval` |
| **Согласовано устно** | Согласие клиента, полученное по телефону | `Approval.isVerbal = true` |
| **Предоплата** | Частичная или полная оплата до начала работ (ТЗ п. 2.5) | `Payment.kind = PREPAYMENT` |
| **Норматив этапа** | Плановое время нахождения заказа в статусе | `StageNorm` |
| **Эскалация** | Автоматическое уведомление при просрочке (ТЗ п. 2.7) | `Order.escalationLevel` |
| **Просрочка** | `now > dueAt` для активного заказа | `Order.dueAt` |
| **Невостребовано** | Готовый заказ, не полученный клиентом 30 дней (ТЗ п. 2.8) | статус `UNCLAIMED` |
| **Акт отказа** | Документ при отказе клиента от оплаты (ТЗ п. 2.8) | `RefusalAct` |
| **Гарантийный заказ** | Повторный ремонт по гарантии, связан с исходным заказом | `Order.isWarranty`, `parentOrderId` |
| **Рекламация** | Претензия клиента, рассматривается 10 рабочих дней (ТЗ п. 2.9) | `WarrantyClaim` |
| **Запись разговора** | Аудиозапись звонка из IP-АТС, хранится 1 год (ТЗ п. 2.4) | `CallRecording` |
| **Сверка** | Сопоставление сумм платежей между системой и 1С | отчёт `docs/06` §7 |
| **ЧекККМ** | Документ 1С, фиксирующий факт оплаты с услугой «Ремонт» (ответ A4) | `IntegrationOutbox` |
| **Квитанция** | Печатный документ, выдаваемый клиенту при приёме заказа | `Order.qrPayload` |
| **`qrPayload`** | Содержимое QR-кода квитанции: `repair://order/{номер}` | поле `Order.qrPayload` |

## Технические термины

| Термин | Значение |
|--------|----------|
| **Минорные единицы** | Копейки. Все деньги хранятся целыми числами, поля `*Minor` |
| **Guard** | Условие, проверяемое перед переходом статуса (например, предоплата внесена) |
| **Effect** | Побочный эффект перехода (проставить `dueAt`, рассчитать гарантию, уведомить) |
| **Data Scope** | Область видимости данных роли (`STORE`, `PRODUCTION`, `ALL_STORES`…) |
| **Transactional outbox** | Запись задачи синхронизации в той же транзакции, что и бизнес-изменение |
| **Идемпотентность** | Свойство операции не давать дубль при повторе; ключ `idempotencyKey` |
| **Keyset-пагинация** | Постраничный вывод по курсору вместо `OFFSET` — не деградирует на объёме |
| **Оптимистичная блокировка** | Защита от перезаписи: `UPDATE ... WHERE version = ?`, конфликт → 409 |
| **PWA** | Progressive Web App: веб-приложение, устанавливаемое на телефон |
| **RBAC** | Ролевая модель доступа |
| **Presigned URL** | Временная подписанная ссылка на файл в S3, живёт 15 минут |
| **Рабочий календарь** | Календарь с выходными и праздниками для расчёта рабочих дней |
| **PITR** | Point-in-Time Recovery: восстановление БД на любой момент времени (RPO ≤ 5 мин). Выполняет **администратор БД**; уточняется, охвачен ли PITR существующей системой копирования |
| **RTO / RPO** | Целевое время восстановления / допустимая потеря данных |
| **Внешний PostgreSQL** | Существующий сервер PostgreSQL 16 предприятия, **общий** с 1С и другими системами. Проект его не устанавливает (ответ A1). Требования — `infra/db/README.md` |
| **Бюджет соединений** | Ограничение пула приложения (`DATABASE_POOL_SIZE`), чтобы не занять все `max_connections` общего сервера БД. Рассчитывается как `пул × число процессов` |
| **Внешний nginx-proxy** | Прокси заказчика, который терминирует TLS (Let's Encrypt) и маршрутизирует трафик. Проект не содержит собственного прокси (ответ A1) |
| **`TRUST_PROXY`** | Число доверенных хопов прокси. `1` — за внешним nginx; `true` запрещено (позволяет подделать IP через `X-Forwarded-For`) |

## Роли

| Код | Название в интерфейсе |
|-----|----------------------|
| `RECEIVER` | Приёмщик магазина |
| `PRODUCTION_MANAGER` | Менеджер обработки поступающих ремонтов |

| `CASHIER` | Кассир |
| `MANAGER` | Руководитель |
| `ADMIN` | Администратор |
| `AUDITOR` | Наблюдатель |
| `CHIEF_ACCOUNTANT` | Главный бухгалтер |

## Статусы заказа

| Код | Название в интерфейсе | Смысл |
|-----|----------------------|-------|
| `DRAFT` | Черновик | Заказ создаётся, данные правятся |
| `AWAITING_APPROVAL` | Ожидает согласования | Клиент думает над суммой и сроком |
| `AWAITING_PREPAYMENT` | Ожидает предоплату | Согласовано, но предоплата не внесена |
| `ACCEPTED` | Принят в работу | Готов к передаче в производство |
| `QUEUED_FOR_DISPATCH` | В очереди на отправку | Ожидает формирования партии |
| `IN_TRANSIT_TO_PRODUCTION` | В пути в цех | Передан курьеру, акт подписан |
| `IN_PRODUCTION` | В производстве | Принят цехом, назначен исполнитель |
| `IN_TRANSIT_TO_STORE` | В пути в магазин | Возврат готового изделия |
| `READY_FOR_PICKUP` | Готов к выдаче | В магазине, клиент уведомлён |
| `UNCLAIMED` | Невостребовано | 30 дней не получен |
| `COMPLETED` | Выдан | Оплачен и передан клиенту |
| `REFUSED` | Отказ от оплаты | Оформлен акт отказа |
| `REFUSED_BEFORE_WORK` | Отказ до начала работ | Клиент отказался до начала работ; заказ вернулся из цеха без работ |
| `CANCELLED` | Отменён | Отменён сотрудником до начала работ |
| `REWORK` | Доработка | Возврат в цех по рекламации |

## Сокращения в коде

| Сокращение | Расшифровка |
|------------|-------------|
| `minor` | Минорные единицы (копейки) |
| `no` / `No` | Number — человекочитаемый номер (`orderNo`, `actNo`) |
| `kkt` | Контрольно-кассовая техника |
| `pbx` | IP-АТС (Private Branch Exchange) |
| `ADR` | Architecture Decision Record |
| `DoS` | Definition of Done — критерии готовности этапа |
