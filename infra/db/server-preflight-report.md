## 3. Блокер: отсутствует право `CREATE`

Проверено запросами:

```
has_schema_privilege(repair_app, 'public', 'CREATE')  → false
has_schema_privilege(repair_app, 'public', 'USAGE')   → true
has_database_privilege(repair_app, 'repair', 'CREATE') → false  (свою схему создать нельзя)
```

Фактическая проверка `CREATE TABLE _probe_perm(id int)` в транзакции с откатом:

```
ОШИБКА: нет доступа к схеме public
```

**Следствие:** миграция Prisma (`40 таблиц`, `14 типов`, `77 индексов`) не
применится. Роль также не может создать собственную схему — прав на уровне БД нет.

**Что нужно от администратора БД** (одна команда):

```sql
GRANT CREATE ON SCHEMA public TO repair_app;
```

Это единственное, чего не хватает. Всё остальное — версия, локаль, расширения,
бюджет соединений, лимит роли — уже настроено правильно.

## 4. Что ещё стоит уточнить у администратора БД

Из `infra/db/README.md` §5.1 остаются открытыми два вопроса, влияющие на
требование RPO ≤ 5 минут:

1. **Включено ли WAL-архивирование (PITR)?** При периодических дампах RPO
   фактически равен интервалу дампа, а не 5 минутам. Если PITR нет — это нужно
   зафиксировать как **принятое отклонение** с реальным значением, а не отмечать
   требование выполненным.
2. **Проверялось ли восстановление?** Непроверенный бэкап не является бэкапом.

Ответы нужны не для запуска в режиме отладки, а для приёмки.

## 5. Риск: память при сборке Next.js

1 ядро и 2 ГБ RAM. Сборка Next.js на таком контейнере может завершиться
OOM-kill на этапе компиляции. Варианты, если это произойдёт:

1. Временно увеличить swap (например, до 2 ГБ) — самый простой путь;
2. Собирать артефакты на другой машине и копировать готовый `.next`;
3. Поднять RAM контейнера в Proxmox до 4 ГБ.

Запуск самой системы (API + веб в режиме `standalone`, без сборки) укладывается в
2 ГБ с запасом — ограничение касается только этапа сборки.

## 6. Порядок развёртывания

1. Администратор БД: `GRANT CREATE ON SCHEMA public TO repair_app;`
2. Установить Node.js 20 LTS (NodeSource) и системные пакеты.
3. Создать системного пользователя, каталог приложения.
4. Передать код, заполнить `.env` (права `600`).
5. `npm ci`, сборка, `prisma migrate deploy`.
6. Проверить `infra/db/preflight.sh` — должен пройти все проверки.
7. Запустить API и веб под systemd.
8. Проверить `/health/ready`, вход и запрос заказов.
9. Настроить маршрутизацию в nginx-proxy (UI): домен → порт 3000,
   `client_max_body_size 25m`.
