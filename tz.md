# ДОКУМЕНТ 2. ТЕХНИЧЕСКОЕ ЗАДАНИЕ НА ИС (CRM)

## 1. Назначение и цели

1.1. ИС предназначена для ведения и контроля работы с заказчиками ювелирного сервисного центра.

1.2. Цели:

- единая база заказов для всех магазинов и производства;
- контроль сроков на каждом этапе;
- фиксация всех согласований (включая устные и записи звонков);
- контроль предоплат и оплат;
- отчётность по загрузке, срокам, выручке.

---

## 2. Функциональные требования

### 2.1. Единая база заказов

- Регистрация заказа в любом магазине.
- Доступ ко всем заказам из любой точки.
- Поиск по номеру заказа, ФИО, телефону, статусу.
- Карточка заказа: клиент, изделие, фото, вид ремонта, история статусов, платежи, согласования.

### 2.2. Прейскурант типовых работ

- Версионность (цена на момент приёма сохраняется в заказе).
- Утверждение руководителем.
- Пересмотр ~1 раз в год.

### 2.3. Калькуляция сложного ремонта

- Отдельные строки: работа по прейскуранту + стоимость камней.
- Расходники включены в работу.
- Возможность корректировки с фиксацией причины.

### 2.4. Согласования

- Фиксация устного согласия: дата/время, сотрудник, сумма, срок, пометка «согласовано устно».
- **Интеграция с IP-АТС**: автоматическая привязка записи звонка к карточке заказа.
- Обязательный пункт заявки о записи разговоров.
- Срок хранения записей — 1 год.

### 2.5. Предоплата

- Приём в любом магазине по номеру заказа.
- Привязка платежа к заказу независимо от места внесения.
- Синхронизация с 1С.
- **Блокировка старта работ** до подтверждения предоплаты (для случаев, где она нужна).

### 2.6. Логистика

- Формирование партий по графику.
- Акт приёма-передачи (электронный).
- Фотофиксация партии.
- Отслеживание статуса «в пути».

### 2.7. Сроки и эскалации

- Нормативы по каждому этапу.
- Автоуведомления ответственным при просрочке.
- Уведомление руководителю при просрочке >1 дня.
- Дашборд просроченных заказов.

### 2.8. Выдача и оплата

- Фиксация оплаты, синхронизация с 1С (ККТ).
- Условие выдачи — полная оплата.
- Акт отказа при отказе от оплаты.
- Статус «невостребовано» через 30 дней.

### 2.9. Гарантия и рекламации

- Признак гарантийного заказа.
- Срок гарантии: 6 мес. / 3 мес. (закрепка).
- Срок рассмотрения рекламации — 10 раб. дней.
- Запись в основном заказе.

### 2.10. Роли и права доступа

- Приёмщик магазина.
- Менеджер производства.
- Мастер-ювелир.
- Логист / курьер.
- Руководитель.
- Администратор.

### 2.11. Отчётность

- Сроки по этапам.
- Загрузка производства.
- Просрочки.
- Выручка.
- Предоплаты.

## 3. Интеграции

| Система         | Назначение                                  |
|-----------------|---------------------------------------------|
| 1С              | Оплаты, ККТ                                 |
| IP-АТС          | Записи звонков, привязка к заказам          |
| СМС/мессенджеры | Уведомления клиенту о статусе (опционально) |

---

## 4. Нефункциональные требования

- Ролевая модель доступа.
- Журнал действий пользователей.
- Резервное копирование.
- Разграничение прав по магазинам (при необходимости).
- Веб-интерфейс (доступ из любой точки).
- Мобильная адаптация (для мастеров и курьеров).

## 5. Этапы внедрения (предложение)

1. Ядро: заказы, роли, прейскурант.
2. Логистика и статусы.
3. Интеграция с 1С.
4. Интеграция с IP-АТС.
5. Отчётность и дашборды.
6. Гарантия и рекламации.

2. **Личный кабинет клиента** (веб) — нужен ли на старте или в перспективе?
3. **Мобильное приложение для мастеров** — обязательно или достаточно веб-интерфейса?
4. **Разграничение по магазинам** — должен ли приёмщик видеть заказы других точек, или только свои + поиск по номеру?
